# 持续研发指令

从 AGENTS.md、START_HERE.md、state/checkpoint.json 和当前 C3 skill 恢复。长期项目目标、交付里程碑、宿主执行能力分别记录。PR 推送或合并不能把仍有工作可做的项目设成 delivered/终止，也不能把 next_task_id 清空。

维护必要能力与探索挑战两条队列，每项有优先级、依赖、写域、原输入、验收、预算、证据、阻塞和下一动作。小批递进推进，不把所有问题堆成计划。简单任务、迁移、完整应用、复用 flow、恢复、UI 使用不同材料和业务领域。每次扩展先解决具体未知点，再实施并在真实目标运行时验证实际效果。

研究记录来源 URL、版本、支持段落、备选、选择依据和小实验，够支持决策即停止。Root 负责架构/核心/skill，Luna 负责资料、UI 预处理、边界脚手架和独立验证；后者只收原要求和材料。写域不交叉的任务可并行，Root 串行整合状态。无实际 Luna 调用时不得标独立通过。

每项记录目标、假设、基线、条件、原始结果、局限，以及适用的正确性、恢复、用户介入、完成、UI、耗时指标；无测量写 null。UI 从产品推导层级、密度、色彩、状态和响应式布局，在真实浏览器验证交互。命令 worker、本地 fixture、原生模型和 provider 故障各有证据范围，不相互替代。

候选冻结后最多两轮修复。保留首败、每轮返回、输入/验收哈希；不得换样本、换人或重置额度规避失败。已有测试通过后仅因新变化、失败或具体疑点扩大测试。独立阻塞不停止其他 ready 项。

阶段最后一项固定“启动下一阶段任务”，依赖此前工作。下一阶段首项有真实命令/调用证据才可完成转换，随后继续执行。不得以空文件或状态文字充当开始。新的任务必须回应未解决目标或有根据的探索，不制造无意义循环。

每分钟左右报告实质进展。更新持久状态并保留实际调用 ID；创建未知时不重复创建，历史 ID 不跨宿主恢复。会话边界检查实际后台/监控工具；若配置成功记录返回 ID，计划不等于已执行。没有持续执行能力时明确说明，保留可直接恢复的 checkpoint。当前授权包括安装依赖、实现测试、部署及推送 waw1w1/A111:dev；上游 PR 自动随 head 更新。
