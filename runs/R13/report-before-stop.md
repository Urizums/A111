# R13 研发规程接入

承接R12同一独立审查者对修订规程的设计通过结论，把冻结v2原样接入docs/EVALUATION_PROTOCOL.md，并在AGENTS.md、START_HERE.md和CODEX_HANDOFF.md给出研发入口。它不进入C8的五文件技能包，也不要求用户安装或运行任何新增脚本。

adopt-command.json记录实际文件写入，是R12后继转换的真实首步；计划本身不视为执行。接入源/目标逐字节一致，新增规程锁保留全部旧revision-lock索引，旧入口/清单版本保存于entry-before/及R12/baseline/。

接入只允许修改三个入口、共享台账、导出清单和追加规程锁；其他4163个基线文件及35条旧任务应由inspection.json实际核对。导出清单仅改变三个入口和新增docs/EVALUATION_PROTOCOL.md的四项，旧清单原件保留。

准备助手的一次纠正补丁被拒绝，第二次恢复并修正预执行发现的多余括号；旧源码和两次累计2/2保留。没有把失败构造从预算中排除，没有原业务重跑。

本阶段是有限文档接入；末项在接入完成后cancelled，说明没有新的有价值、可绕过原阻塞的后继，而不是生成新样本来延长阶段。长期项目active，R08主阶段不推进，R10/R11原依赖不改判。当前没有后台调度。

规程已接受的是设计，不是它能实际提高业务成功率的结论。C8仍为可审阅开发候选，原行为验收未通过；CI和完整性核对只支持各自检查范围。
