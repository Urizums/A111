# R23 工作流能否自行推导验证范围

本阶段只验证一个尚未被R22回答的设计问题：在收到C13和业务题目、没有协调者预写的42日研究协议时，新上下文能否把交付期限、信息更新方式、决策单位和结论边界转化为可执行的实验及接收接口。R22按协调者冻结的详细协议完成计算，并不能证明工作流设计者能自行推导这些要求。这个差别关系到用户关心的稀疏任务输入和smoke强度。

复用已锁定的R21原始历史数据及现政策源码，只改变本阶段请求和角色信息边界，不改写旧输入/输出/失败。另给中性业务简报：未来42日一次性固定计划、整数资源限制、需求及版本、需要预测/区间/备货/比较/论文；不发送旧工作流、研究协议、论文、结果、诊断或独立验收答案。原数据已知，整个试验称定界的设计迁移探查，不称新盲测、skill因果增益或Level1–4重跑。

| 任务 | 写域与依赖 | 原件接收要求 |
| --- | --- | --- |
| R23-01 | audit/；依赖R22-next | 冻结中性请求、输入身份、角色边界和接收要求；实际从原CSV核对可用日期/版本及固定交付范围，不拟合或读取私有未来 |
| R23-02 | design/；依赖R23-01 | 新工作流设计者仅读C13、中性业务题和原件，自行制作可转交的工作流、主张—证据与执行接口、可操作首步，不获协调者研究方案 |
| R23-03 | execution/、review/；依赖R23-02 | 另一消费者实际执行设计所选择的一条有实质意义的验证切片，新接收者从原件核验设计/接收界限；只检查切片支持的结论，未覆盖完整论文不称完整生产 |
| R23-04 | final/、candidate/；依赖R23-03 | 将具体失败追溯至设计或源条款；确证一般源缺口才另版纯文档并作受影响前瞻接收，否则保留C13；没有要求新策略胜出 |
| R23-next | 后续依赖全部完成 | 本定界支线完成后明确结束；只有新的实质用户目标或具体未解决缺口才提出下一工作，不制造重复回放 |

接收要求事先另锁，设计者不收到验收预期方案。对42日固定交付，设计应说明各关键主张由哪种同信息/期限/更新方式/评价单位证据支持；较短历史实验可作为有限证据，但不能自动接收完整期限的可靠性。原件确实不足时，定位缺口、选择可执行补证或保留未验证状态，同样可以是正确设计。不得为通过强制固定窗口数、算法数、页数或同期限实验配额。

接收者必须检验：接口是否足以让另一上下文操作；边界是否由实际题目推导；如何防止引用基准配置替代适用性判断；切片激活了哪项条件；结论/语言与未验证范围是否一致。接收者不读取生产者自检和诊断，作者自检/代码重跑/独立判断分开。动作需要真实原始证据，首次失败及分类修复原样保留，未知actual model/token/cost为null。
