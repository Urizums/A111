# R16：不接触既有解法的真实 MathorCup 赛题试解

用户本轮新增要求：由子 agent 独立写一份上半年 MathorCup 或九月国赛的真实题解决方案，不抄袭、不看当时参赛论文或已有解法。Root 选择 2026 上半年 MathorCup 常规赛；只取得官方题面、附件及勘误，不查询九月国赛。题目选择依据原材料可取得、本科组、应用建模与现有 CPU 可执行性，不依据答案或获奖模板。

这是一条新增明确授权的真实赛题支线，补充 R14 微型题的外部有效性，不替换 R14 的任何输入、失败、验收、预算或被阻塞的 R15。C9 继续是原八文档冻结版本，作者预算 2/2 不变。常规赛实践不等于大数据赛通过，也不等于实战获奖。

1. R16-01 取得并核实官方原材料。子 agent 只读取官方 MathorCup 原题/数据/勘误页面，保存来源、时间、字节、哈希与缺口，中性摘录不附模型建议或结果。外部论文、获奖论文、社区解法、答案和题解不进入输入包。
2. R16-02 在原题取得后冻结真实题要求、数据与原创试解验收；新上下文子 agent 使用原 C9，从题意拆解、数据审查、baseline、候选比较到求解、验证、图表与完整论文，逐问覆盖题面。代码和论文属于试解产物，不能混入技能包。不搜索解法，网络关闭；必要背景未知写明。每个有界执行案例最多两轮累计失败驱动纠正，保存所有失败及计数域。
3. R16-03 由另一新上下文审查原题、原数据和冻结工件。独立复算重要结果、检查代码与模型及论文、实验公平性与数据可用时间、边界/敏感性、图表、原题覆盖和复现。审查者不给作者的标准答案/诊断，不能以论文存在或作者 pass 判通过。
4. R16-04 Root 汇总实际证据，区分题面覆盖、数值正确、方法合理、实验充分、论文一致与尚未支持的竞争力；报告向十月大数据赛迁移的相同能力与差异。真实终端/CPU限制、模型/token/cost未知保持明确。
5. 启动下一阶段任务：依赖以上原要求完成，选择有实际价值且可执行的下一项，并保留真实首步。若依赖、材料、预算或宿主能力阻塞，末项 blocked，不人为制造阶段或放宽验收。

Root 串行持有真实租约并整合共享状态。来源者只写 runs/R16/source/，生产者与审查者另有独立写域。只做已结束题的研发练习，不投稿、参赛提交或声称原创新算法。原题与数据来源应标注，解决过程独立性与论文引用规范分别检查。
