# R22 独立接收准备计划

准备阶段范围：只在本目录写准备源、计划和命令收据。此阶段只核对协议/输入/算法源身份及允许的来源接口，不运行模型、不计算预测或备货、不阅读任何 R22 execution 内容，也不形成科学接收判断。`identity_check.py` 只校验锁定字节身份。

## 已核对的规范和身份

- R22 唯一接收标准为 `runs/R22/protocol/acceptance.json` 的 h1–h6，并按 `runs/R22/protocol/PROTOCOL.md` 的固定实验接口执行。历史原件已被 R21 使用，因此报告必须称为知情的固定策略历史回放；不得称新盲测、部署选择或 skill 因果试验。
- R22 协议锁为 `runs/R22/protocol-lock.json`。R21 原材料身份来自 `runs/R21/input-lock.json`。R21 原算法身份来自 `runs/R21/execution-lock.json` 中明确获准的源文件、冻结配置、来源预测追踪和训练/特征/促销插补/系数文件；`prospective-freeze.json` 仅用于识别原策略和来源时点。
- 仅读原材料 `runs/R21/inputs/**`；仅读算法源 `runs/R21/execution/source/v1/{config.json,reference_policy.py,run_science.py}`、`runs/R21/execution/prospective-freeze.json`、根 execution 锁，以及协议列明的来源轨迹/训练快照/特征/系数文件。不得打开其余 execution 文件、旧论文、评价、生成器、自检、诊断、报告或预期数值。
- 允许阅读的 C13 材料只限 `runs/R20/final/candidate/C13/forge-agent-flow/**` 中的纯文档。它不是科学门槛，也不能改变 h1–h6。
- 初始上下文出现了 R21/R22 报告路径指针；没有据此打开报告或结论材料。历史数据已知这一事实不会因独立重算而变成盲测。

## 冻结后独立计算步骤

1. **先冻结接收实现和配置**：root 授权正式接收前，停止编辑本目录。授权后 root 冻结本目录源文件及其身份；接收者不看作者自检、诊断、结果汇总或 root 的预期数值。正式阶段每条命令通过 `py -3.12 -X utf8 -B scripts/record_command.py --out runs/R22/review/receipts/<唯一名>.json -- <真实命令>` 执行；等待所有子进程终态再记收据，未知模型、token、费用为 `null`。
2. **重建原始数据身份和 as-of 训练**：从锁定 raw CSV 独立读取，折叠整行重复，拒绝同键同修订冲突；检查修订到达单调性、时间戳 Asia/Shanghai、维度键、单位/有限值。每个历史原点只保留 `available_at <= origin` 的每键最高修订，并严格排除 `service_date >= origin 日期` 的训练行。逐键与获准的原 train CSV、快照哈希和训练特征核对。重算近期促销均值时只用原点前56日且 `announced_at <= origin` 的记录；天气只标注当时已发布的 forecast，不能把 observed 或事后天气写成已知输入。
3. **独立重建两条固定策略**：从协议常数构造 96 店品、56 品星期、8 品 time30、8 品促销、活动项×0.3 的169列；无额外截距 Ridge(alpha=10) 使用冻结 solver，预测截为非负。W 路线为同店品、近56日星期均值，缺历史星期组时回退同店品训练均值。只用两个冻结策略，不调参、不选胜者、不加方法配额。逐原点确认 grid 的键/信息接口一致。
4. **重建成熟残差日向量**：逐个 `residual_coordinates_all.csv` 来源坐标回到 raw demand 报告，按 2026-11-04 18:00 的最高修订定位成熟行，匹配来源记录实际使用的版本与到达时点。误差以成熟 `demand_units - published point` 重算，point 按接口的10位小数精度解释；`error` 字段只作差异诊断。按 `source_origin`、训练快照 SHA、来源点预测与成熟版本/到达时间关联。只收来源原点严格早于目标原点、服务日已结束、所用版本已到达目标原点、且该日96个唯一坐标全部就绪的整日向量；其它同窗日期是否就绪不影响某个合格日。禁止当前目标窗、重叠未来窗、未来真值补齐或重复日期加权。
5. **3窗全量重算并比较**：原点固定为2026-07-22、09-02、09-19 Asia/Shanghai 18:00，之后42日×96键。每路线每窗必须有4032唯一行。生成连续实数情景 `max(point + residual, 0)` 和 numpy linear 5%/95%分位（10位小数），行动变量保持整数。按同资源、同目标独立逐日求解，复算目标值、状态/bound/gap、1600件与6000元约束。先核全量行键/单位/有限性，再报告预先定义的总体、1–14/15–42、六个7日带、活动/普通、活动×步长、店、品、日期配对指标。空活动格保留0日期/0键和不可估计状态。前两窗84天可作描述性合并；09-19与09-02重叠25日，单列为端点压力窗。
6. **实质边界与独立计算对照**：实际构造边界输入：公布时点晚1秒、95/96坐标、同一14日窗中完整与不完整的不同日、合法实数情景、非有限点/情景、非整数/超界/超资源行动。小型实例穷举对比独立求解目标和约束；不能把生产者自己的同源测试当独立证据。clean explicit-output rerun 单独记录，并确认写入新空输出目录、拒绝覆盖；另保留 raw 原件独立重建和关键结果重算，不能以重跑替代独立重建。
7. **中文消费物检阅**：先完整通读最终 Markdown 和附录，核对方程、单位、定义、关键表述、图表来源及正文数值与独立数据。再确认最终 PDF 页面数和图形资源，逐页渲染成 PNG；按页码一页一图实际查看每一页，不以文本抽取、缩略图或抽样代替。另用 PDF 文本抽取检查断字/乱码/缺页，与 Markdown 逐节核对；将检查到的实际页面范围、图表编号和问题记入收据。修订后的 PDF 需重新渲染并逐页再看。正式阶段处理 PDF 前按要求读取 PDF skill。
8. **首判和报告**：只按 h1–h6 逐项记证据/缺口；不套获奖分数、模型数量或页数门槛，不新增失败门（特别是区间必须包点预测），不弱化真实约束。清洁复现、作者自检、独立重算、人工阅读分别列证。若首判有缺陷，原首判和失败证据保留，修复另域另锁，不倒写。

## 实际消费者查看流程细节

- PDF 文件页数来自 PDF 解析器，页面渲染必须完整成功；比较页数与最终文件实际页数，检查空白页/页面裁边和图表是否跨页断裂。
- 生成便于翻阅的全页 PNG 后，按顺序打开每张 PNG，记录 `page n / total` 已查看；接收者放大查看小字号表格、脚注、坐标、图例、单位、中文字体和页码。缩略图总览只用于检查整体节奏，不能代替逐页阅读。
- 抽取 PDF 文本用于与 Markdown 核查标题、公式和关键数值；图像/文字渲染仍以实际页面图为最终视觉证据。图表逐张核对坐标/单位/图例及其对应表值，正文的未来限制、窗口重叠、历史已知与活动空格陈述逐处核对。
- 每次 PDF 重建都记下 PDF SHA256、页数、渲染命令和最终页面查看清单。最后一次编辑若影响页面，必须重新完成全页查看。

## 准备阶段边界

本准备阶段没有读任何 PDF，也没有做模型拟合、策略评分、情景或备货计算；当前收据仅记录真实读取与锁定身份核验。进入正式阶段需要 root 在准备源冻结后另行授权。届时只获准读取协议、R21原材料、获准算法源码/身份、允许的来源追踪文件、实际生产交付以及PDF skill；不读取执行者的自检/诊断/结论或 root 的预期答案。
