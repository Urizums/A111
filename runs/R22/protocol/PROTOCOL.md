# R22 固定42日历史回放协议

本协议在本轮首次拟合/策略评分之前冻结，承接R22原计划和已完成的原件可用性审计。问题是：原两策略在各历史原点固定未来42日时的预测、区间和备货表现如何；早期1–14步与远期15–42步是否不同；数据/活动分布允许怎样的结论。已有历史曾被R21使用，因此这是知情的固定策略历史回放，不叫新的盲测、当时已部署的选择或skill因果试验。禁止读取R21私有未来真值、生成机制、旧论文/结论或作者诊断来选模型。

## 固定数据、策略与信息接口

- 原点：2026-07-22、09-02、09-19的Asia/Shanghai 18:00；每原点从次日开始42日，每日12店×8品共96键，每路线每窗4032唯一键。每天重新备货、无跨日库存，资源0–55整数/店品、总量≤1600件、采购≤6000元；目标仅缺货与报废两项损失，采购是资源约束。
- 历史评估标签：原始demand_reports按11-04 18:00可见最高修订，服务日≤10-31；训练则只用各原点已公布最高修订且服务日严格早于原点日期。整行完全重复可折叠，同键同修订冲突应拒绝。原点后版本可用于评价，不能倒灌训练、特征或残差池。
- R：共享ridge(alpha=10、无额外截距)，96店品+56品星期+8品time30+8品促销+活动项×0.3，共169列；time30从05-01开始。预测非负，未知促销采用原点训练近56日已公布品均值，天气排除。W：同店品星期近56日均值，必要回退同店品训练均值。两个方法原样固定，没有调参、新选路或胜出配额。
- 只按原点已公布促销/天气形成接口；记录字段与时点，即使天气不参与拟合，也不能把事后天气标为当时已知。同原点两路线允许使用不同的已知特征子集，但网格、标签、资源和损失一致。
- 残差来源固定为R21首锁的14日源预测轨迹，`residual_coordinates_all.csv`只提供来源接口。按其source_origin、train_snapshot_sha256、原point和所用成熟标签修订/到达时点回溯原件。仅严格更早的source_origin、已结束的服务日、96坐标所用版本全到齐的日向量可入池；同源窗其他日期未齐不排除合格日。不得新增本窗/重叠窗未来残差、重复同一日加权或把未来已见真值补入。
- 残差重算为成熟历史标签−该原源预测的已发表point（10位小数），不信任现成error列作为真值。该已发表精度是明确的接口迁移；不声称内部未舍入逐位相同。向量等权；各目标日情景=max(新point+整日残差,0)。情景可为实数，行动q必须整数。
- 区间为同情景numpy linear 5%/95%分位，按10位小数输出。只要求finite、非负、lo≤hi、点预测非负、标称0.9；偏差残差的中心分位区间不必包含点预测，不增加此伪门或为通过而裁剪。原R21已冻结断言及首判不改。
- 优化沿用同一两项期望损失凸边际整数MILP，mip_rel_gap=1e-9；资源每天独立检查。求解status/bound/gap及目标重算保存；有界可行不等于获得真实性能或最优性证明。

前两窗口目标日期不重叠，可单独报告其84个日期的描述性合并结果；09-19窗口与09-02重叠25日，作为端点压力回放单列。不得把三窗重复键混成新的独立样本，不作显著性/因果或名义90%保证。每历史窗活动4日，与原固定未来规划活动频度不同；同期限不自动代表同业务机制。跨窗口训练可依法包含较早目标已公布标签，这是历史信息接口，不是模型选择授权。
