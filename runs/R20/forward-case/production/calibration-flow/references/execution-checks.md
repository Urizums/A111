# 可执行检查和交接

先写要求→原来源→可观察断言→输出字段→检查人→拒绝条件。选择几个有意义条件做小冒烟，但未覆盖要求保留在全量验收。

1. Preflight：校验输入身份/配置/schema、运行时及来源可访问；只证明准备就绪。
2. Smoke：从实际原表执行到可消费表格和短说明，重新核算至少一个完整向量及一项缺失。必须激活时间边界，例如等时刻标签、未来修订或原预测补写；文件数量和退出零不足以通过。
3. Rejection：实际生成保留的坏来源或坏产物，如同版本矛盾、未到达标签被选入、缺失坐标被补造，实际运行生产/接收端。要求出现有依据拒绝和非成功终态；坏产物不得成为正式结果。明确这是作者测试，除非另有盲测设计不要称独立评测。
4. 全量接收：对所有原点用原表另路重算选中版本/时间资格/残差/完整性/来源引用；表格和科学说明一致。对于参数依赖的量明确算术容差。独立性重要时另设授权的新上下文，只给原要求、原始输入和实际产物，不给标准答案、作者诊断或前一判定。
5. Clean rerun：用同输入与交付源码，在此前不存在输出目录、最好不同工作目录运行。比对数值语义或确定性字节，记录新的命令身份，不能冒充原调用。
6. Delivery：交付可读入口、全部原点表、代码/配置、执行说明、已做检查及不足、输入和产物身份、失败历史和 checkpoint。未知模型/token/成本写 null；不从文件大小或角色名称推算。

代码和测试放 skill 目录外。重跑用新输出目录，禁止覆盖原结果掩盖失败。记录原始命令失败及未启动子进程的构造失败；不要重演副作用补填原日志。工具错误修复保留错误和变更路径；实质修复指出违反的原要求并重跑受影响断言；正常模型迭代记录未决问题、比较与结果。任何固定试验约束仍按原条件保留原判定，后续政策变化只对未来适用。

交接下一动作应与实际状态相符：作者完成可交给独立接收者；真实阻塞说明缺什么及可独立继续的工作；已完成目标可取消无需进行的阶段转换。说明文件或计划本身不是实际运行，也不提供发布/后台任务权限。
