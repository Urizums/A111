# 输入、选择及输出合同

## 输入

- 坐标表：非空、不重复的 `series_id`。其顺序为向量顺序。每个完整日期都需要全部坐标。
- 预测表：`target_date, series_id, revision, forecast_origin, available_at, prediction_units`。
- 标签表：`target_date, series_id, revision, available_at, actual_units`。
- 决策配置：时区和非空新原点列表；评价截止为可选上下文，不能自动授权提前使用未来标签。

字段名称可映射，必须保留原定义。到达与截止为同一时区的带偏移时刻；物理实际/预测量有限、单位一致，revision 为正整数。不得把 NaN/Inf 当缺失或让它参与排序/残差。未知坐标、无时区、冲突单位拒绝或明确转换并保留依据。日期不能单独决定可用性。

预测版本键包含 `(target_date, series_id, forecast_origin, revision)`；标签版本键为 `(target_date, series_id, revision)`。同版本完全相同重传合并，保留全部行引用。同版本内容或到达冲突拒绝；没有协议授权就不能擅自把冲突当新版本。修订和重传均不增加坐标。多个固定预测原点要先明确选哪个预测集合，不能不加声明地混合。当前参考程序要求输入只含一个已选择的固定预测原点；另一任务可以扩展接口而保留审计。

## 政策

**最新已到达政策**：每个新原点 o，筛选 `available_at <= o` 的标签，选择最大 `(available_at, revision)`。原点等时刻可用；同到达时刻不同版本取最高 revision。对每个坐标，预测先满足 `available_at <= forecast_origin <= o`，再用相同排序选原截止内的版本；原截止后补写永远不能修改原预测。

**固定成熟政策**：提前声明评价版本选择截止/规则，确定每个坐标固定评价版本，只有其真实到达不晚于 o 才纳入。不能因为目标日期已过去或“评价完成”字样就认定可知。若评价版本未来才到达，保留不可用原因；如果所有日期都不成熟，给出空池，不改用最新政策隐式救场。不能混用两种政策或忽略来源到达。

选中坐标携带预测和标签的完整源字段、源文件/行号/字节哈希，残差及状态。无合格预测或标签则残差空缺，状态可定位。未选版本审计应区分原预测迟到、决策时尚未知、已被修订替代、完全重传；一个来源可同时违反两个时间条件，但给出首要原因并仍可从原字段复核两个条件。

## 下游消费

- 逐项表：每原点×目标日×必需坐标恰好一行；版本、原截止、到达、源引用、量、残差、状态。
- 日状态表：必需/已具备/缺失坐标、完整标记、是否纳入、完整向量到达；部分日期不填虚假向量到达。
- 校准向量表：每原点仅包含完整日期，每日期恰好一条，明确坐标顺序和单位。
- 版本审计、原输入哈希、配置与政策；跨原点更新不解释成相互独立样本。
- 短科学说明：公式、政策、实际结果、排除/不足、范围及复现入口。所有数字有结果字段与原来源双向定位。

消费者重新核对原输入定义，不能信任产物自行声明的“当时可用”。逐项量值用十进制算术或合适容差重新计算；完整日须检查全集并取到达最大值。空池是可解释结果；有无足够样本用于某校准器是另一个明确条件，不能用文件存在代替。
