## 原件驱动的数值接收方法

1. 从原始 types 展开全部 item_ids，建立 ID → 原始类别/尺寸/质量映射。每件必须恰好出现一次，检查未知、重复、遗漏 ID；车辆类型绑定原始 vehicles。输出中携带的身份或物理字段若与原件冲突，应保留并报告冲突。
2. 在比较、支撑、聚合前验证全部相关物理数值为有限数值；布尔值不作坐标、质量或费用。原始尺寸/质量/载重/费用须在实际有意义的值域。数量需要非负整数语义；坐标及费用 NaN/Inf 不能靠普通不等式被放行。
3. 按固定原始朝向用坐标恢复每件盒体，逐轴检查非负、车内边界及顶部 clearance；以三轴开区间交叠判定体积重叠。零厚度接触不作重叠。默认数值算术容差 1e-9 m，仅处理计算舍入，不能改变原始阈值。
4. 非落地件须在同车内找到恰好一个底面被其完整覆盖、接触高度相等的下层件。仅水平相邻不构成支撑，拼接支撑不替代单件完整支撑。下层必须是 standard；fragile 可落地或在 standard 顶上，其顶面不得承载货物。
5. 构建上件 → 支撑件关系。逐件把原始质量沿其全部祖先链累加，得到每个 standard 的累计外载，除以原始顶面面积与原始阈值比较。自己的质量不算自己的外载。检查递归链、fragile 的非零外载和支撑循环/无支撑。
6. 按原始单件质量求每车载重，按实际使用的原始车型费用重新计算车辆数和费用；空车声明单独暴露，不用作者汇总替代实际使用车辆。原件是先最少车、再最小费用的字典序目标，不能换成权重和。论文若称最优，要有与该原件目标匹配的下界/可行上界或其他有效证明；否则只能给可行性和已证明界限。

`independent_check.py` 是依据上述原件自行写的物理检查逻辑。它的 canonical interchange 只是接收者内部结构，不是对作者新增的强制文件模式；正式阶段依据冻结输出做可审计、无损转换，并保留原输出身份。检查器返回原始身份冲突和实际错误列表、重新计算的目标、质量、支撑关系、累计外载及激活情况。不能把检查器 exit0、文件存在或作者的 valid 字段等同于验收。

## 论文和 PDF 接收

采用可用 PDF 技能的只读渲染流程：确认实际 PDF 和源文身份；抽取文本用于关键内容定位，但不据此推断渲染保真；用已可用的 Poppler 将完整 PDF 渲染为 PNG，并逐页实际查看。原件不设篇幅、模型数量、固定段落文案或任意排版风格阈值。只判定是否有完整、清晰、可验证的中文科学论证，以及实际导出是否保留关键科学含义。装车已给条件的证明不能改写为轴载、振动、装卸通道或现场运输认证。

## 已执行的准备控制和能力限制
