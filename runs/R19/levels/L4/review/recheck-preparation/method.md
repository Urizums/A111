# L4 知情复审准备方法

本准备发生在首次首审已冻结、新版尚未交接时。已知首审的 a4 fail、a6 partial 与真实 NaN 反例，因此后续明确标 `informed_recheck`，不冒充新的盲审。当前不读取活跃 execution-v2，不判断任何新版产物，不修改 initial/或 preparation/。初审锁164文件实际全部匹配。只在收到 root 的新生产目录/锁授权后，在另一个 recheck-1 写域执行。

## 待解决的原实质缺口

首审 D1：用原冻结最终单车方案的合法地板 G1 行，只有 x 改为 NaN，原附件校验CLI仍退出0/VALID/errors=[]；事前独立检查拒绝 invalid_numeric。NaN 不是题面每件真实摆放坐标，也不能满足 DOCX P16—19的几何意义。新版必须在任何几何比较、载荷、目标汇总和成功标记之前拒绝无效数值，不能静默转0或默认值。当前旧有限结果的可行性与论文实证不因 D1 自动失效。

首审另观察不可装单件虽非零退出、不产生成功summary，但只有矩阵乘法维度 traceback，没有清楚说明货物无法装入任一车型。检查新版是否给出可理解的原因、对象和适用条件；不强加特定错误文案或私有JSON字段。

## 受影响的接收与控制

正式接收先验证 initial-lock、原件/评价/设计及新锁；检查新程序附件核心代码与新生产源码一致。先读变更内容和运行合同，再安全解压到消费者副本，从官方原件独立重建输入。所有测试输出/日志只写 recheck-1，不使冻结新版生成pycache或日志。

合法与非法控制必须实际同接口执行，而不是只阅读源码。合法基准为首审已证明合法的真实地板G1单件行、原完整官方数据、合法0坐标、边界接触和至少一组有明确支撑的有限方案；合法行应通过，不能为堵NaN把所有输入拒绝。完整场景保证不是合法单件的替代。

| 控制域 | 实际变体 | 检查断言 |
| --- | --- | --- |
| 摆放CSV | x/y/z和l/w/h分别出现NaN、+Inf、-Inf；空/非数值字段选择有代表性的实例 | CLI明确非成功且不能产valid=true或可消费成功汇总；原独立检查器拒绝；不静默修补 |
| 坐标值域 | 负x/y/z、非正l/w/h、正体积重叠、高度安全余量不足 | 按原几何/源尺寸约束明确拒绝；保留合法边界/0坐标配对 |
| 数据数值 | 货物尺寸/单重、车型尺寸/载重/费用中的代表性NaN/±Inf及非正物理值 | 程序在求解前清楚拒绝所影响字段；不无限开车/把错误结果当可行；费用允许范围按正式公开输入合同及原目标解释 |
| 库存 | 负数、非整数和非有限数量；零数量的一类但整批仍有货为合法配对 | 不能截断、强制补1或偷偷丢类型；原公开非负整数合同被遵守；不额外要求全零实例一定可解 |
| 配置 | 代表性的非有限间隙/承重阈值/容差，明显违反其物理及公开配置范围 | 应拒绝而非用False比较放行；参数场景与原场景不同规则明确标识，原场景仍满足3cm |
| 不可装货 | 新建一件各方向均比所有车型更大的刚性箱，保持其余字段有效 | 明确不能装入任何候选车，非成功状态，无成功完整方案；原因不是隐藏的shape/矩阵异常 |

控制身份和期望来自旧真实反例、官方几何要求、原程序明确的输入合同；不预填新版通过、目标数字或新算法排名。枚举有限性字段是系统性修复同一个比较机制失效，不是添加模型数量或页数配额。若新版合理支持比旧合同更广的输入（如零费率），先按其公开数学定义验证边界，不把旧的可逆格式偏好当作新的官方强约束。

所有成功/失败必须记录真实命令、返回码、stdout/stderr、输出身份/是否valid=true、独立期望及实际观察。数值反例可批量跑，但每个实际结果要保留。包装器要在昂贵调用后立即落盘，NumPy标量先转Python原生值，避免首审补充记录丢失；失败不擦除，不重演旧副作用冒充旧receipt。

## 新程序附件与关键完整场景

新包安全解压并比较核心源码哈希。按新版公开入口用独立原件重建数据做一次实际清洁全量主路径；复核四个原整批目标场景及所有最终单车方案。逐件原尺寸/方向、完整库存/ID、每车边界/可能相交对、安全高度、易碎/定向、完整支撑、累计载荷/接触压力和原定义UV/UW/费用独立重算。若仍为单父模型，沿用冻结独立单父逻辑，代表车力矩验证；出现多支撑/新语义则补受影响几何及受力检查，不继承旧pass。

新结果不要求车辆数或坐标与旧版完全相同；要求原题目标、合法性、诚实界/启发式限制和新论文数值一致。若相同，分别报告字节一致、规范化坐标一致或仅目标/语义一致，不能用旧已知数字预填。实际变更输入至少一个有意义库存/尺寸/载重小实例，确保程序计算及接收仍有效；与拒收控制分开。无需强制重跑全部历史算法研究或17参数优化。

## 证据复用与科学论证一致

旧证据只能按具体字节身份与依赖影响范围复用：原件、评价、未变设计；首审全文科学论证与15页可读性；37组旧坐标、64附件2几何、39主表与合法界；旧三路线公平条件、17参数与机制解释。它们证明旧版范围，不自动证明新包或新输出。新锁中相关论文、图表、参数数据若字节完全不变且数值/约束依赖不变，可明示复用具体首审条目；任何文字、公式、图表、配置、选中结果或生成代码改变，阅读/复算相应内容和下游主张。至少确认新版最终消费稿能打开，查看变更页，并将新版推荐和关键主表定位到本次检查。

特别核对修复是否只增强数值接收或无意改变目标、库存、易碎姿态、安全间隙/压力，及企业报告的异常/不可装操作说明是否与程序一致。旧最优性未知不能被修validator提升成已最优；旧附件2缺字段不能被有限性补丁填成实测。若复用未改变的科学论证，明示没有再次重复全部历史研究，不虚称所有实验重新运行。

## 判定与终态

正式 recheck-1 保留首审原status和 a1— a6，不改 initial。逐项更新本次受影响 a4/a6，及任何实际变更影响到的a1/a2/a3/a5；六维仍按原冻结定义给证据、材料缺口、下一动作，复用项注明身份与范围。没有新生产证据时全为 pending/not_evaluated，不能预判新版。

控制修复成功不足以独自通过整个交付；必须新附件实际可跑、关键完整场景独立检查、新结果与科学稿一致。原缺口若继续出现，用实际反例拒绝；日志不充分就写unverified而非猜测。未知provider/model/token/cost保持null，无通用两错即停或自造整任务短deadline。

本准备仅冻结方法与控制规格，没有在新版运行任何检查。终态后停止写入并通知root；正式知情复审另待新锁授权。
