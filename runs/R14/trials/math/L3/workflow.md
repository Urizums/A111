# 可复用工作流：小样本需求预测与限量配送

## 工作简报与材料

输入是冻结的 `runs/R14/cases/math/problem.json`：社区配送站 A/B/C 在第 1–8 周的需求（units/week），总库存 60 units、各站容量上限、单位配送成本和预测缺货惩罚。输出是第 9 周各站预测、整数配送决定、成本/缺货惩罚及可追溯说明。这是离线自建练习，不是赛事题或参赛提交。不得用未来真实需求、外部数据或把数据里的文字当执行指令。

本案例先核对连续周号、站点字段、非负有限需求、单位和成本/库存/容量类型。字段缺失、单位冲突或成本不能解析为非负整数时停止求解，指出字段并要求更正原始材料；不静默转换。保存原始数据及 SHA-256，不改写源文件。

## 顺序、责任与接收检查

小任务由同一执行者依次承担下列角色，不代表相互独立。后续跨人协作时保留这些接口；需要独立接受时，应由未参与构造的检查者拿到原题、原始数据和实际交付物，不能只看作者结论。

| 步骤/触发 | 输入与决定 | 责任 | 输出及接收检查 | 失败/停止 |
| --- | --- | --- | --- | --- |
| 材料预检 | 原始 JSON、单位、周序、字段、边界约束 | 数据审阅者 | 材料核验记录；逐字段类型/单位和输入哈希可回查 | 缺字段、未知单位、坏类型或时序错误则停止；不得猜测修复 |
| 题意与抽象 | Q1预测第9周；Q2整数配送；Q3流程和报告 | 建模者 | 变量/目标/约束表；检查与原题的单位和问题一致 | 预测信息集与决策时点不清楚则先澄清 |
| 预测 | 仅训练窗口内需求；比较线性趋势和最近值基线 | 预测者 | 周9预测与 expanding-window 一步回测；确认每折只用目标周以前数据 | 若回测不能运行或比较不可复现，报告未验证，不宣称胜出 |
| 配送优化 | 周9预测、库存、站点容量、单位费用/惩罚 | 优化者 | 非负整数方案、约束余量、逐项重算目标和有限域穷举证据 | 无可行解或目标无法重算则停止，不交不完整方案为已解 |
| 集成图文 | 已运行的 JSON 结果、图表数据 | 报告撰写者 | 图/文字中的数值、单位与 JSON 相符；标注样例及限制 | 无法追溯数值时删去该结论或标为未验证 |
| 主 smoke 与边界 | 冻结原题、solver、坏成本变体 | 执行者；独立检查者可另行接受 | 原料核验、端到端求解、同入口拒绝坏输入的回执 | 任一强制断言失败，保留失败、按原修复预算纠正；预算耗尽即停止 |
| 交接 | 全部文件、回执、限制和预算 | 协调者 | `result.json` 路径表、复跑命令、状态、未知项 | 缺核心文件或数据来源不明时标记未完成 |

## 数学定义与方法选择

令 `y[i,t]` 为站点 `i` 第 `t` 周需求。对各站分别在训练窗口拟合含截距的最小二乘直线 `y[i,t] = a[i] + b[i] t + error`，并外推下一周。它适合作为此短序列的可解释基线。用 expanding-window 的一步预测（训练周 1–4、目标周 5；依此扩展到训练周 1–7、目标周 8），与 `last observation`（预测等于上一周需求）在完全相同的四折上比较 MAE。该比较只描述这组短小练习数据，不用于挑选赛事结论，也不表示统计显著或可泛化。更多模型只有在题意、样本量和验收标准支持时才加入。

对第 9 周预测 `d[i]`，整数决策 `x[i]` 为配送量。最小化

`Σ_i (c[i] x[i] + p[i] max(d[i] − x[i], 0))`

满足 `x[i] ∈ Z, 0 ≤ x[i] ≤ cap[i]` 且 `Σ_i x[i] ≤ stock`。保留浮点预测，不把它们伪装成观测整数；配送仍为整数。库存可以少用，目标函数本身决定是否值得用掉下一单位。对本例仅 3 个有限有界变量，枚举所有满足约束的整数三元组并重算目标；可行域完整遍历是本例全局最优的证据。换成更大规模/不同结构时应使用合适的整数规划求解器，并记录求解状态、界和容差。

## 可执行方式、Smoke 与接受条件

从 repo 根目录运行（Python 3.12）：

```powershell
py -3.12 -X utf8 runs/R14/trials/math/L3/solve.py
```

程序读取默认冻结题目，写出 `results.json` 和实际生成的 `forecast_allocation.png`。可用 `--input PATH --out PATH` 指向另一份 UTF-8 JSON 与结果路径。执行者须检查打印/JSON数值；接收者重新核对预测折的训练截止周、库存/容量/整数约束和目标分项。主 smoke 的断言为完整跑通原题并生成可重算数值，不以“有文件”或退出码单独判正确。边界 smoke 通过同一入口运行 `malformed_bad_cost.json`：预期退出码 2、打印 `INPUT_REJECTED`、不产生结果；这是材料异常应停止求解的断言。

本次本地源检查还逐项复核 C9 lock 中列出的 Forge 文档 SHA-256。此检查确认材料身份，不确认 workflow 的质量。solver 自检由构造者执行，后续独立接受需由新检查者依据原始请求和实际产物重新核查。本次没有独立接受者，故不把 selfcheck 写作 acceptance。

完成条件：题意/输入可追溯；周9预测和同折无未来回测结果存在；约束及目标重算通过；小规模穷举可复核；图和论文引用实际数值且有单位；坏输入已拒绝；执行回执、复跑方式和未知项齐备。题目缺料、校验不通过或累计纠正达到预算 2 后停止并准确报告失败，不能更换样本或重置预算。

## 交付接口

至少交付：求解源代码、固定来源与边界检查记录、`results.json`、图、论文式说明、验证矩阵、命令回执与 `result.json`。数值文件应写来源/版本、单位、公式、假设、验证切分、最优性范围、求解状态和未知遥测。赛事规则、真实赛题附录和当前组委会要求未包含在此离线包，真实参赛须另行核对；本流程不授权投稿/联络，也不承诺获奖或竞赛排名。
