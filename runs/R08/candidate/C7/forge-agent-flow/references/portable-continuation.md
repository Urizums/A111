# Continue across owners and hosts

Keep one project goal and its original failure history. Separate handoff,
implementation acceptance, and measured effectiveness. A closed PR or stopped
collaborator changes ownership; it does not erase unfinished requirements.

## Recover the source

Pin the actual repository commit. Capture original checkpoint, task ledger,
acceptance and materials as bytes before mutating them. Index useful code,
commands and evidence with their actual claim limits. Keep previous absolute
paths and worker IDs as historical data; query only calls belonging to the
current host, never recreate an old receipt or replay uncertain external effects.

Keep the old active phase as an explicit interrupted/blocked history entry.
Register the new authorized phase in the same ledger with a takeover reason;
do not mark the old transition done. Distinct newly observed defects and new
business goals may get new task IDs. Retrying the same exhausted frozen case
requires an explicit revised experiment decision; preserve the old verdict and
budget and explain which new claim is being tested.

## Classify a blocker by the capability it consumes

Record each blocked requirement, evidence, required capability, observed probe
and next action. Distinguish local code defects, validator/harness defects,
missing observations, exhausted experiment scope and absent service/permissions.
Do not describe all unfinished work as a missing replica of the user's computer.
Run portable local branches when checkout/command access exists. Run native
coordination only when native worker tools are actually present. Leave provider
SDK, device UI, global usage and cancel-terminal claims pending their own probes.

## Execute and record native coordination

Choose the smallest sufficient task decomposition. Keep a one-time conversion
direct. Use children for genuine independent work or source review, and assign
disjoint output paths. Give each child raw materials, outcome requirements and
the fixed skill path; keep author diagnostics and expected answers away from
independent reviewers. Persist intent before creation and copy the actual host
receipt after it. Record final replies, outputs and current status before
integration. If creation returned an unknown result, reconcile rather than spawn
again. Model config and elapsed observations support only their captured scope;
unavailable usage/cost fields are null.

Check CLI help and artifact envelopes before expensive validators run. Count
each failure-driven source change in the declared implementation or validator
budget; keep the scopes visible. Exit zero, child creation and a plausible
summary do not prove task acceptance. Review source identity, outputs, omissions,
original rules and failures, then record the result and actual successor first
step. Native children, subprocesses and service workers prove different layers.

## End a bounded batch

Save current frontier, outstanding calls, consumed budgets, blockers and the next
useful action. Preserve disabled timers. Publish an explicitly scoped development
handoff when authorized, with unresolved acceptance clearly visible. Do not claim
full product acceptance or speed improvements from one pilot. A planned successor
needs actual work evidence before the phase transition can be completed.
