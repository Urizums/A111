# Roles with checkable handoffs

Read for delegation and integration. Delegate only when the user/host authorizes
it and the extra context solves a real dependency, expertise or independence need.
Do not spawn a full roster just because a workflow names Research/Data/Model/Code/
Review/Paper. One role can own several compatible steps; labels do not confer
independence, security isolation or a specific model.

The coordinator owns shared requirements, core decisions, integration, priorities
and final delivery. Workers own separable outputs and return evidence. Serialize
shared state; give parallel writers separate domains and explicit merge contracts.
Directory instructions are cooperative boundaries, not enforced security isolation.

A task packet contains:

- Original relevant requirements, raw input identities, actual tools/permissions.
- Required output/interface and consumer, dependencies and read/write boundary.
- Self-check or acceptance responsibility, assertions/evidence and current budget.
- Completion/stop criteria, unresolved decisions and expected handoff.

For a fresh acceptor withhold intended answers, author diagnoses and other actors'
verdicts. It needs original requirements and enough raw artifacts to verify the
claims. Assign what it must recompute/inspect and which observed contradiction
would reject the output. Do not ask it merely to bless the producer's smoke log.
An acceptor may add justified tests, but must not impose optional preferences as
new mandatory requirements or alter frozen thresholds to force a pass.

Keep research, production, reception and independent acceptance distinct in the
record, even if some roles share a context. Researchers return provenance and
qualified claims. Producers return reproducible artifacts and self-checks. A
Paper/UI consumer may use only what the prior receiving gate permits; unresolved
results cannot become established conclusions by being rewritten attractively.

For review that must be independent, check the actual receiving channels
before dispatch: user/raw inputs, attachments, selected history, tool
arguments/outputs, auto-summaries and accessible shared artifacts as relevant
to the host. Forward the smallest sufficient source-and-artifact packet;
keep author diagnoses, expected answers and prior verdicts out of what
the acceptor can actually see. A short allowlist/check is often enough.
Use a detailed manifest only for complex or high-risk transfers. If the host
cannot expose/control inherited history, mark independence unverified rather
than pretending a directory boundary is isolation.

Handoffs carry requirement/task identities, inputs actually used, concrete outputs,
source pointers, assumptions/conflicts, checks actually performed and limits,
original failure/budget history, state and next action. The receiver checks the
interface and evidence before reuse; a prose completion claim is insufficient.

Use actual task identities, returns and status for host-created actors. Reconcile
unknown creation/termination before duplicate calls. Use actual status/cancellation
facilities; local workflow text cannot control provider-wide concurrency. Capture
only minimal evidence; do not make each worker build a recording framework.
Requested model and authenticated provider telemetry are separate; unknown model,
time, tokens and cost stay null/unknown.
