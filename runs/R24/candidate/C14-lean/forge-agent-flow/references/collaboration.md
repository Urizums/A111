# Collaboration when it earns its cost

Delegation is useful when separate work can proceed safely, particular expertise is needed, or verification must genuinely be independent. It is not a default requirement for every flow, and a coordinator does not need to instantiate a named roster merely because a template mentions one.

The shared goal, original user requirements and integration decisions need a clear owner. Give each worker enough of the actual materials to perform its assigned part and a concrete description of what the next consumer expects. For complex work, include the input version, output boundary, permitted write area, dependencies, acceptance and resource limits. For a small handoff, a concise message with those essentials can suffice.

Parallel work should have compatible interfaces and nonconflicting ownership. If several workers modify the same state, specify who integrates and reconciles it. Local instructions to write in separate folders are coordination conventions, not hard security isolation.

## Independence must be real

A producer can self-check its output. A reviewer can separately inspect the result, but *independent or blind acceptance* requires actual information separation, not just a different role label. When that property matters, give the acceptor the original task, source material and actual artifact; avoid expected answers, author diagnoses and prior verdicts.

Examine the channels the host really forwards: visible conversation history, automatic summaries, command arguments, tool logs and shared artifacts may expose material that was not explicitly attached. Use the smallest sufficient clean packet and verify it where possible. When the host cannot control or show inherited context, report the review as informed or independence unverified.

A helpful receiving report says what requirement was checked, against which actual source/artifact, what observation supports or rejects it and what remains outside the judgment. A reviewer may identify new risks, but optional advice does not become a retroactive mandatory condition.

Keep actual dispatch identities, observed status and unresolved calls. An unknown outcome of a potentially side-effecting action should be reconciled before re-dispatch. Requested model labels are not authenticated telemetry; missing model/cost/time remains unknown.

Use [evaluation](evaluation.md) for substantive receiving checks and [continuation](continuation.md) when handoffs span sessions. Do not invent a recording framework where real host receipts already supply what is needed.
