# Keep work resumable without manufacturing work

For a substantial ongoing project, preserve the goal, authoritative inputs and candidate versions, accepted output and the evidence behind it, original failed attempts, unresolved calls, real resource limits and the next useful action. A short ordinary task does not need a persistent program management system.

On resumption, inspect what actually exists and what the current host can do. An old PID, status line or agent name is not proof a process still runs. Reconcile potentially side-effecting calls before retrying; reuse earlier output only when its input, version and receiving checks still apply.

When a dependency is blocked, other authorized independent work can continue. Do not claim that it closes the blocked gate. If the user authorizes a change to future policy, keep the original experiment, budgets and verdict and document what applies prospectively. A new experiment cannot retroactively repair an old trial.

Distinguish two loops. **Task delivery** stops when the requested outcome is accepted or truthfully blocked. **Capability research** may continue if the user authorized it and another meaningful question or class of task is available. That research should select a new test for a reason, not simply rotate through a fixed number of task categories.

A transition counts as started only when an actual next action happens. If the next step is unavailable, unjustified or outside authorization, record that condition instead of marking a planned stage complete. A TODO file cannot itself run background work or authorize a submission.

Before handing off, make it easy for the next executor to answer: what is settled, what is uncertain, what failed, what can safely be done next, and what evidence would change the decision. Use the repository's existing state tools if available; do not make the portable skill depend on any one ledger format.
