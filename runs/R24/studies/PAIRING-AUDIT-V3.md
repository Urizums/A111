# R24 配对实验：评分退出码与交付路径安全修复（V3）

本轮是对 **实验工具可信度** 的缺陷修复，不是对 C13 或 C14-lean 的能力判定。候选 Skill 原件和历史旧实验均不改动。

## 发现与复现

1. V2 的 `grade` 命令即使两个参与者都没有 `submission/`、两组 `artifact_passed` 全部为 `false`，仍返回进程退出码 **0**。原因是顶层返回逻辑只检查 `result.get("passed")`；原 `grade` 返回值根本不包含该字段。命令行调用者容易把失败误作成功。
2. V2 会接受把 `submission/answer.json` 设为指向研究者隐藏 `expected.json` 的**符号链接**；在不正确隔离的宿主中，这个危险的输入别名会被当成正常答案。上轮文档正确指出“目录不是安全隔离”，但实际判分器仍缺少最基本的本地路径防护。
3. V2 在没有外部可信冻结哈希时也可能返回退出码 0。虽然回执写明没有外部验证，自动化入口仍可能误把这种仅供诊断的评分视作可用验收结果。

原版 V2 和失败重现保存在 Git 历史及本次审计记录中，不能被后来 V3 的通过结果追溯覆盖。

## 本次代码变化

V3 将每个参与者的两个概念分开：`frozen_input_issues` 表示已冻结原任务/Skill 输入有问题；`submission_issues` 表示实际成果路径不安全、缺少文件或包含符号链接等。必需成果必须是真实、大小有界的普通文件；冻结的任务/Skill 目录不能被替换成目录符号链接。其他一般性附加文档依旧**只记录额外负担**，并不为了减少文件而自动判业务失败。

评分回执升级为 `forge-r24-paired-grade/2`，新增 `artifact_checks_passed`：只有两组必要成果都通过自动化产物检查，才为 `true`。命令行进程只有在 **(a) 两组产物检查通过，(b) 外部可信冻结哈希已供核对且匹配** 时返回 `0`；任意失败返回 `2`。没有外部冻结令牌时依然可生成诊断回执，但不会向自动执行器发出绿色成功信号。

特别注意：进程退出码 0 **不是** AI 独立性、`workflow.md` 语义可用性、资源公平性或 C13/C14-lean 胜负的验收。回执仍是 `winner: null`，`comparison_result: not_established_no_independent_actor_receipts`。
