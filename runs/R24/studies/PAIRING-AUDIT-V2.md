# R24 配对实验身份归属修复（2026-10-10）

## 发现的问题

R24 `paired_experiment.py` v1 先用随机种子打乱两个候选的 A/B 名义归属，之后却始终按固定臂名拷贝 `C13` 到 `arm_a`、`C14-lean` 到 `arm_b`。当名义标签交换时，参与者实际读取的 Skill 与冻结清单里的版本标签相反。原 18 项自测只检查“候选标签不同”和“文件被哈希冻结”，没有检查标签与复制内容的对应性，不能验证实验归属正确。

首次复现：用 C13、C14-lean 两份包含显式版本标记的假 Skill，在 v1 依次生成种子 0–9 的实验，其中 6/10 个出现版本归属错误。**因此 v1 的配对实验实例不得用于比较候选优劣，不能重新判定或隐藏旧缺陷。** 截至本轮，两版真实 Agent 的正式执行仍未开始，没有受到污染的正式胜负结果可修复。

## 修复和拒收规则

新版本先按候选名称读取原始 Skill 并计算每个文件的 SHA-256，再随机确定 A/B 标签，**根据抽取后的候选名称拷贝其真实文件**；复制后立即检查其源 SHA 清单。冻结清单格式升级为 `forge-r24-paired-trial/2`，新增 `variant_source_sha256`，评分时再次检查 A/B 的候选声明和其文件哈希是否对应。

旧版 schema `/1` 会直接被拒绝，不再悄悄作为可评分的配对实验处理。仍然保留旧版的 Git 历史和本次失败证据；新的试验应重新生成新种子，并将完整冻结清单哈希交给实际宿主在参与者不可见的可信位置保存。仅在同一可读文件夹中保留 SHA 不能证明隔离。

## 真实回归（作者本地，非独立 Agent）

- `python -m py_compile paired_experiment.py` 通过。
- `python paired_experiment.py selftest` **22/22 通过**（旧 18 项 + 4 项针对版本随机交换和来源归属的检查）。
- 新版本逐一生成 20 个不同种子，两种随机归属均被触发，实际 `skill/SKILL.md` 所含版本与私有冻结清单一致。
- 人为修改冻结清单中的某个臂版本名而不修改实际源文件，评分拒收；人为将新实例伪装成旧 `/1`，评分也拒收。
- 原有结果检查、缺交付、来源变动、Skill 改动、隐藏真值变动、额外文件只记负担而非失败、冻结哈希校验等回归仍通过。

以上观察只证明研究工具可以正确归属候选并拒绝特定混淆。**没有执行两个真正的独立 Agent，也没有证明 C13 或 C14-lean 在未见任务上更好。** 在真实宿主启用前，继续增加合成样例已不是首要研发任务。
