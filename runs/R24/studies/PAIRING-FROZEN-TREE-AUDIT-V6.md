# R24 V6 — 冻结参与者输入树漏检修复

本次修复不是新增 Skill 规则，而是纠正配对实验评分器 `check_frozen()` 的实际边界缺陷。

## 复现

仓库 V5 只核对预期文件名称与 SHA-256。它以 `is_file()` 枚举文件，忽略了未登记的目录，因此无法察觉嵌入 `task/` 的额外子目录、嵌入 `skill/` 的目录符号链接，以及参与者根目录额外的说明。此时正常预期文件完全没变，函数仍返回空错误数组。作者在本地对上述三个实例实际复现了此情况，并验证 V5 原函数 Git Blob `41a7cd8b075477e54cadd01d82a804bb244cc1d7` 与能够本地执行的 V3 原函数字节完全一致。

## 修复

新逻辑保留原来冻结文件逐个哈希检查，同时枚举 `task/` 与 `skill/` 的**所有路径，包括目录和符号链接**。只有冻结文件的必要父目录能出现；新增目录、文件、符号链接或其他非普通条目将触发错误；参与者根目录只允许 `task`、`skill`、`START_HERE.md`、`submission` 四种条目。

在本地同一原函数与相同修复补丁上，原 V3 的 27 项自测加 4 项边界检查，**31/31 通过**；正常 `references/` 仍允许、额外任务目录拒绝、符号链接目录拒绝、根目录额外文件拒绝。提交前逐字节核对了新函数与新增测试片段的 Git Blob。详情见 [机器回执](PAIRING-FROZEN-TREE-V6-RESULT.json)。

### 必须保留的边界

本地完整执行的是带原样 `check_frozen` 的 V3 测试环境及新补丁，**没有在本机完整检出 V5/V6 或实际运行独立 Agent**；不把片段的 31 项通过写成整个 V6 已经在完整仓库跑完。GitHub 原有 CI 也不自动代表 R24 所有私有研究自测已经执行。文件树检查不提供沙箱、权限控制或可验证独立性；实际试验仍必须通过宿主隔离 `reviewer_private`、对臂与隐藏真值。

C13/C14-lean 的原始九文件内容、旧 V1–V5 证据和主 R08 checkpoint 均未修改。R24-03A/B/C 真实多 Agent 试验仍未完成。
