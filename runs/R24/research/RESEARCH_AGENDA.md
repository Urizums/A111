# 后续 Research Agenda：可证伪问题与检索策略

每项研究分成“为什么现在研究”“原假设”“可能推翻它的证据”“最小实验”“产物/下一决策”。研究优先服务未解决的业务/架构决策，不以论文数量、关键词或查询次数评分。检索外部资料必须核原始出处、版本和适用范围；过去聊天或仓库经验不能替代新的真实观测。

## 按问题收集材料

- 事实/标准：优先当前官方原文、版本历史、原文件、可复现仓库；必要时核不同解释与过时条款。
- 方法/工程：比较实际接口、故障案例、开源测试和可重复的最小原型；外部 Skill/Agent 实现只能借具体机制，不能直接借“成功”标签。
- 研究论文：重点查任务拆解、计划验证、工具失败恢复、信息泄漏、评价器偏差、多代理成本和人机接口；论文需明确任务/数据/成本/评价与可迁移限制。
- 社区经验：可用来寻找未知失败模式、实际不可用环境、UI 使用反馈；需向原始可重复材料追溯，避免转载堆数。
- 负结果：记录未命中、权限拒绝、矛盾与为什么停止某检索路径；“没搜到”不是“没有”。

## 单张可重用知识卡

| 字段 | 填写内容 |
| --- | --- |
| claim_id | 稳定编号和适用的原需求/假设 |
| observation | 原始观察；指出与解释之间的边界 |
| source | 具体仓库路径/commit/网页 URL/段落/时间 |
| applicability | 任务类型、输入与版本、工具/host、限制 |
| counterevidence | 相反事实/缺失证据 |
| proposed_mechanism | 具体会改变哪个决策/接口/检查 |
| experiment | 新未见任务、冻结条件、主要和负面指标 |
| outcome | planned/observed/pass/fail/inconclusive；不能先填成功 |
| next_decision | 保留、修复、废弃或补研究及其条件 |

## 把知识卡升级成 Skill 的门槛

必须指出可复现的非个案缺口或跨条件必要的职责；新规则相较 C13 产生可观测改进；未增加不必要的普遍强制工作；文档与真实 executor 接口一致；至少记录局限。未满足时，经验留在研究库/案例库，而非继续扩张九份 Markdown。
